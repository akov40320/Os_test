# Бронирование столиков

Небольшой API для бронирования столика в ресторане. Можно создать бронь, посмотреть все брони или одну по номеру, а ещё отменить бронь.

Брони пока хранятся в памяти. Поэтому после перезапуска приложения список начинается заново. Для тестового этого достаточно — в задании как раз разрешено использовать обычный словарь.

## Как запустить

Нужен Python 3.11 или новее.

**Windows (PowerShell):**

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

**Linux / macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

После запуска документация API будет здесь: http://127.0.0.1:8000/docs

## Что умеет API

| Метод | Адрес | Что делает |
|---|---|---|
| `POST` | `/bookings` | Создать бронь |
| `GET` | `/bookings` | Посмотреть все брони |
| `GET` | `/bookings?date=2026-12-15` | Найти брони на дату |
| `GET` | `/bookings/{id}` | Посмотреть одну бронь |
| `DELETE` | `/bookings/{id}` | Отменить бронь |

Пример запроса для создания брони:

```json
{
  "name": "Иван Иванов",
  "phone": "+79991234567",
  "booking_date": "2026-12-15",
  "booking_time": "19:00",
  "guests": 2
}
```

## Правила бронирования

- Имя — от 2 до 50 символов.
- Телефон — в формате `+7XXXXXXXXXX`.
- Дата — сегодня или любой день в течение следующих 30 дней.
- Время — целый час с 12:00 до 22:00.
- Количество гостей — от 1 до 10.
- На одну дату и время может быть только одна активная бронь.

Если время уже занято, API вернёт `409`. Если данные не прошли проверку — `422`. Для несуществующей брони будет `404`.

При отмене запись не удаляется: у неё меняется статус на `cancelled`. Поэтому её можно будет найти по ID, а освободившееся время — забронировать снова.

## Тесты

Запустить тесты можно командой:

```bash
pytest -v
```

Тесты проверяют создание, получение и отмену брони, фильтр по дате, занятые слоты и основные ошибки валидации.

## Как устроен проект

```text
os_test_backend/
├── app/
│   ├── api/
│   │   └── bookings.py                 # адреса API
│   ├── repositories/
│   │   └── memory_booking_repository.py # хранение броней в памяти
│   ├── services/
│   │   └── booking_service.py          # правила работы с бронями
│   ├── dependencies.py                 # получение сервиса для запросов
│   ├── main.py                         # запуск FastAPI
│   └── schemas.py                      # проверка входных данных и ответы
├── tests/
│   └── test_bookings.py
├── .gitignore
├── README.md
└── requirements.txt
```

Роуты принимают запросы, сервис отвечает за правила бронирования, а репозиторий хранит сами записи. Брони держу в обычном словаре — для этого задания этого хватает, и не нужно настраивать базу данных. Проверка свободного времени и создание записи выполняются под блокировкой, чтобы два запроса одновременно не заняли один слот. При отмене бронь не удаляется: меняется только статус, а время снова становится свободным.
